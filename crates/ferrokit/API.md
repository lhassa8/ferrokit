# ferrokit 0.7.1 API

Every public item of `ferrokit`, and the `ferrokit-core` types it re-exports, on one page: the signature as written and the first paragraph of its docs. Generated by `scripts/api-md.sh` from rustdoc; the full docs, and the guide, are on [docs.rs](https://docs.rs/ferrokit). Items are grouped by the source file that defines them.

AI coding agents: read `AGENTS.md`, beside this file, first: the rules, recipes and known limits. This page is for looking up what a type can do.

Conventions: views are built once and update from signals; models (`TableModel`, `TextModel`) are created once; row indices are model indices; text offsets are UTF-8 bytes; everything runs on the main thread.

## App and windows (lib)

- `pub fn right_to_left() -> bool`: Whether the app lays out right to left: its language is Arabic, Hebrew, Persian or Urdu (the app's localisation and the user's languages), or the `NSForceRightToLeftWritingDirection` default is set. Ferrokit mirrors its layout then, as AppKit mirrors its own.
- `pub fn layout_times_us() -> Vec<f64>`: Microseconds of the recent layout passes, oldest first (diagnostic; at least the last 10,000).
- `pub fn layout_passes() -> u64`: Layout passes so far. With `layout_times_us`, the times of the passes since an earlier count: `let t = layout_times_us(); &t[t.len() - (layout_passes() - n0) as usize..]`.
- `pub fn open_tab(beside: &NSWindow, window: Window) -> Retained<NSWindow>`: Opens `window` as a new tab of `beside` (the tab bar's + and a "New Tab" command use this).
- `pub fn toggle_full_screen(window: &NSWindow)`: Puts `window` into full screen, or takes it out (as the green button and View ▸ Enter Full Screen do).
- `pub fn is_full_screen(window: &NSWindow) -> bool`: Whether `window` is in full screen.
- `pub fn set_dock_badge(badge: Option<&str>)`: The Dock icon's badge: a count or a short word (`Some("3")`), or none.
- `pub fn dock_badge() -> Option<String>`: The Dock icon's badge, if any.
- `pub fn open_with(make: impl FnOnce() -> Window) -> Retained<NSWindow>`: Opens the window `make` builds, now, and returns it: the signals `make` creates (a form's fields, a selection) belong to the window and are freed when it closes. Prefer it to `open` in an action: a signal made in an action outside any view lives as long as the app.
- `pub fn open(window: Window) -> Retained<NSWindow>`: Opens `window` now (while the app runs) and returns it.
- `pub fn open_settings() -> Option<Retained<NSWindow>>`: Opens the app's Settings window (see `App::settings`), or brings it to the front, and returns it. `None` if the app has none.
- `pub fn close_window(window: &NSWindow)`: Closes `window` and tears down its views (its node is dropped: effects stop, native views go). The app no longer lists it in `windows`.
- `pub fn windows() -> Vec<Retained<NSWindow>>`: The app's windows, in the order they were opened.
- `pub fn later(f: impl Fn() + 'static)`: Runs `f` on a later pass of the main run loop.
- `pub fn set_appearance(appearance: Appearance)`: Sets the app's appearance; every native view follows, and an `AppEvent::AppearanceChanged` is delivered.
- `pub fn quit()`: Ends the app (as ⌘Q does), on the next pass of the run loop. Quitting can wait for answers (a document app asks about unsaved changes) inside a nested run loop; starting it outside the caller's batch keeps the UI updating meanwhile.
- `pub fn spawn<T: Send + 'static>(work: impl FnOnce() -> T + Send + 'static, then: impl FnOnce(T) + 'static)`: Runs `work` on a background thread, then `then` with its result on the main thread, inside a `batch`. Call from the main thread.
- `pub fn spawn_with_progress<T: Send + 'static>(progress: &Signal<Option<f64>>, work: impl FnOnce(&Reporter) -> T + Send + 'static, then: impl FnOnce(T) + 'static)`: `spawn` for a long job that reports how far it is: `progress` reads `Some(0.0)` at once, the fractions `work` reports through its `Reporter` as it goes, and `None` once it's done (just before `then` runs; also if `work` panics, when `then` doesn't run). ### `Window`

`pub struct Window`: A window to open when the app starts.

- `pub fn on_drop_files(mut self, extensions: &[&str], action: impl Fn(Vec<std::path::PathBuf>) + 'static) -> Self`: Files dropped anywhere on the window (that its views don't take themselves) go to `action`: those with one of `extensions`, or any file if it's empty. The pointer shows a copy badge over the window while they're dragged.
- `pub fn new(title: &str) -> Self`: A titled, resizable window of 800 × 600 points.
- `pub fn sidebar(mut self, view: impl View) -> Self`: A sidebar beside the window's `view`, as in Mail, Notes and the Finder (AppKit's split view controller): full height, under the title bar, on the sidebar material; the title and toolbar items start beside it, a Toggle Sidebar button leads the toolbar, and the user can drag it narrower, wider or shut. Put an `outline` or a source-list `sidebar` in it.
- `pub fn sidebar_hidden(mut self, hidden: &Signal<bool>) -> Self`: Whether the sidebar is hidden, bound two ways: setting it shows or hides the sidebar (animated), and the user's toggling sets it.
- `pub fn inspector(mut self, view: impl View) -> Self`: An inspector after the window's `view`, as in Keynote and Xcode (AppKit's inspector split item, macOS 14): full height, a Toggle Inspector button ending the toolbar, the user can drag it wider or shut.
- `pub fn inspector_hidden(mut self, hidden: &Signal<bool>) -> Self`: Whether the inspector is hidden, bound two ways.
- `pub fn tabbing(mut self, tabbing: Tabbing, group: Option<&str>) -> Self`: How the window joins its app's other windows as tabs. Windows join those with the same `group` (all the app's, if `None`); the Window menu's Show Tab Bar, Merge All Windows and the tab bar's + work as in any Mac app.
- `pub fn no_full_screen(mut self) -> Self`: No full screen: the green button only zooms (a palette, a small utility). Resizable windows can go full screen by default.
- `pub fn panel(mut self, style: PanelStyle) -> Self`: Makes it a panel (`NSPanel`): floating above the app's windows, hidden while the app is inactive, and not in the Window menu's list of documents.
- `pub fn toolbar_style(mut self, style: ToolbarStyle) -> Self`: How the toolbar sits with the title (`ToolbarStyle::Unified` by default).
- `pub fn hide_title(mut self) -> Self`: Hides the title in the title bar (it still names the window in the Window menu and Mission Control): for windows whose content says what they are.
- `pub fn transparent_title_bar(mut self) -> Self`: A title bar without its own background: the window's background shows through it, so the title bar and content read as one surface.
- `pub fn full_size_content(mut self) -> Self`: Content under the title bar and toolbar, which become transparent. The content's backgrounds and materials, and a `split`'s panes, reach the window's top edge (a sidebar's material runs up behind the window buttons, as in Apple's apps), while the content itself starts below the title bar.
- `pub fn background(mut self, color: Color) -> Self`: The window's background colour (the system's window background by default). Named colours follow Dark Mode.
- `pub fn size(mut self, width: f64, height: f64) -> Self`: The content size in points.
- `pub fn view(mut self, view: impl View) -> Self`: The window's content: `view`, laid out to fill the window.
- `pub fn toolbar(mut self, items: Vec<ToolbarItem>) -> Self`: A unified toolbar with these items.
- `pub fn customizable_toolbar(mut self, name: &str) -> Self`: Lets the user customise the toolbar: Customize Toolbar… on its right-click menu (and in a View menu, with `customize_toolbar_item`) opens AppKit's sheet, where items can be added, removed and moved, including optional ones and spaces; Command-dragging moves them too. The layout is remembered under `name` across launches; until the user changes it, the app's own layout shows.
- `pub fn on_command(mut self, command: Command, action: impl Fn() + 'static) -> Self`: Handles `command` while this window is focused and nothing nearer the focus handles it (see `Command`), wherever the focus is: in the content, the sidebar or the inspector.
- `pub fn on_command_when(mut self, command: Command, enabled: impl Fn() -> bool + 'static, action: impl Fn() + 'static) -> Self`: Handles `command` like `on_command`, enabled only while `enabled` returns true.
- `pub fn remember_frame(mut self, name: &str) -> Self`: Saves the window's position and size under `name` whenever they change, and reopens it there next time (AppKit's frame autosave, in the app's user defaults).
- `pub fn content(mut self, build: impl FnOnce() -> Retained<NSView> + 'static) -> Self`: A plain `NSView` as the window's content (escape hatch; no layout).

### `Tabbing`

`pub enum Tabbing`: Whether a window opens as a tab of its app's other windows (`Window::tabbing`).

- `Automatic`: As the user set in System Settings ▸ Desktop & Dock ("Prefer tabs").
- `Preferred`: Always as a tab, as Safari's and the Finder's windows do.
- `Disallowed`: Never as a tab, and no tab bar (a settings window, a viewer).

### `PanelStyle`

`pub enum PanelStyle`: A panel's kind (`Window::panel`): a secondary window serving the main ones, which hides while the app is in the background.

- `Floating`: Stays above the app's other windows: an inspector, a palette, a find panel. It becomes key only when a field in it is clicked, so the main window keeps the keyboard.
- `Utility`: As `Floating`, with a slimmer title bar: tool palettes.
- `Hud`: A dark, translucent heads-up panel over media or a canvas.

### `ToolbarStyle`

`pub enum ToolbarStyle`: How a window's toolbar sits with its title (see `Window::toolbar_style`).

- `Unified`: The title and toolbar items in one bar (the default).
- `UnifiedCompact`: One bar, shorter: for windows with few toolbar items.
- `Expanded`: The title above the toolbar, items labelled (as in Settings windows). The other styles show symbols alone.
- `Preference`: The title above the toolbar, items centred (Settings' tabs).

### `AppEvent`

`pub enum AppEvent`: What the app hears about its environment.

- `AppearanceChanged`: Dark Mode or the accent colour changed. Read `is_dark` / `system_colors`.

### `App`

`pub struct App`: The application: a name, its windows and the AppKit run loop.

- `pub fn new(name: &str) -> Self`: An app called `name` (shown in the menu bar).
- `pub fn window(mut self, window: Window) -> Self`: Opens `window` at launch. Call more than once for several windows.
- `pub fn translations(self, tables: &[(&str, &str)]) -> Self`: The app's translations: `(language, .strings text)` pairs, e.g. `("de", include_str!("../locales/de.strings"))`. The languages here are the ones the app speaks; see `t` and the `l10n` functions.
- `pub fn menu(mut self, title: &str, items: Vec<MenuItem>) -> Self`: Adds a menu to the menu bar, between Edit and Window ("View", "Go"…). A menu titled "Edit" adds its items to the standard Edit menu (after Find), and one titled "Help" fills the standard Help menu. A menu titled "File" fills the standard File menu instead, above its Close item. Items run in a `batch`; their enabled and checked states are evaluated when the menu opens or a key equivalent fires.
- `pub fn about(mut self, credits: &str, link: Option<(&str, &str)>) -> Self`: Credits for About {app}: `credits` under the app's name, icon and version (from the bundle), and `link` (title, URL) after it, e.g. `.about("Made with Ferrokit.", Some(("ferrokit.dev", "https://…")))`.
- `pub fn settings(mut self, window: Window) -> Self`: The app's Settings window: "Settings…" (⌘,) in the app menu opens it (built on first use, then brought to the front). It isn't resizable or listed in the Window menu, and it remembers its position.
- `pub fn documents<T: Clone + PartialEq + 'static>(mut self, kind: DocumentType<T>) -> Self`: Makes this a document app for `kind` (see `DocumentType`): the File menu gets New, Open…, Open Recent, Save, Save As… and Revert to Saved; closing an edited document asks to save it, and quitting reviews the unsaved ones. With no windows given, the app starts with an untitled document.
- `pub fn welcome(mut self, make: impl Fn() -> Window + 'static) -> Self`: A welcome window for a document app, shown at launch instead of an untitled document (as Xcode's is): recent documents, a sample, Open… `make` builds it each time it opens. It closes when a document opens, and Window ▸ Welcome to … (⇧⌘1) or `show_welcome` brings it back.
- `pub fn menu_bar_extra(mut self, extra: MenuBarExtra) -> Self`: Adds an item to the right side of the menu bar, with a menu or a panel (see `MenuBarExtra`).
- `pub fn menu_bar_only(mut self) -> Self`: Makes this a menu-bar app: no Dock icon and no menu bar of its own, only its `menu_bar_extra`s (and any windows it opens).
- `pub fn dock_menu(mut self, items: impl Fn() -> Vec<MenuItem> + 'static) -> Self`: Items for the Dock icon's menu (Control-click or a long press on the icon), above the system's own: "New Window", a recent item. `items` runs each time the menu opens, so it can read the app's state.
- `pub fn on_open_url(mut self, f: impl Fn(&str) + 'static) -> Self`: Links in the app's own URL schemes: `f` gets each one opened while the app runs or that launched it (`myapp://open?id=3`, from a web page, another app or `open` in Terminal), after its windows are up. Declare the schemes in `Cargo.toml` and `cargo ferrokit` registers them with macOS when it bundles the app:
- `pub fn crash_reports(mut self, f: impl Fn(CrashReport) + 'static) -> Self`: Crash reports. From now on, a panic Ferrokit doesn't catch (one outside a control's action, menu item, timer or the like, which `on_error` hears about and survives; or one on a background thread) writes a report before the app ends: the app, its version, macOS, the thread, the message and where, and the backtrace, in `~/Library/Logs/<app>/Crashes`. At the next launch, after the windows are on screen, `f` gets each report not yet marked sent: ask the user to send it, send it to a service, or keep it.
- `pub fn on_launch(mut self, f: impl FnOnce() + 'static) -> Self`: Runs `f` on the first run-loop pass after the windows are on screen.
- `pub fn on_command(self, command: Command, action: impl Fn() + 'static) -> Self`: Handles `command` when nothing nearer the focus does (or no window is open). See `Command`.
- `pub fn on_error(self, f: impl Fn(&Failure) + 'static) -> Self`: Calls `f` when something fails where AppKit called into the app (an action, a menu item, a timer, a notification, a sheet's completion): an Objective-C exception or a Rust panic, caught there so the app goes on (it's also printed to stderr). Log it, or tell the user.
- `pub fn on_event(self, f: impl Fn(AppEvent) + 'static) -> Self`: Calls `f` for every `AppEvent`.
- `pub fn run(self)`: Creates the menu bar and windows, then runs the AppKit run loop. Does not return while the app is running.

### `Appearance`

`pub enum Appearance`: The app's appearance.

- `System`: Follow the system setting.
- `Light`: Always light.
- `Dark`: Always dark.

### `Reporter`

`pub struct Reporter`: What a job started by `spawn_with_progress` reports its progress through, from its background thread.

- `pub fn report(&self, fraction: f64)`: How far the job is, from 0 to 1 (clamped). Cheap to call often: the signal gets the latest value on the main thread's next pass.

## signal

- `pub fn after_batch(f: impl Fn() + 'static)`: Registers `f` to run after every outermost batch, once its effects have run (the layout pass hooks in here).
- `pub fn batch<R>(f: impl FnOnce() -> R) -> R`: Runs `f`; effects triggered inside run once, when the outermost batch ends.
- `pub fn effect_runs() -> u64`: Total effect runs on this thread so far (diagnostic).
- `pub fn live_signals() -> usize`: Live signals in the arena (diagnostic: freed ones are reused).
- `pub fn untrack<R>(f: impl FnOnce() -> R) -> R`: Reads signals inside `f` without subscribing the running effect to them.

### `Effect`

`pub struct Effect(Rc<EffectInner>)`: A side effect that re-runs when the signals it read change. It stops when the handle is dropped.

- `pub fn new(f: impl FnMut() + 'static) -> Effect`: Runs `f` now, and again (once per batch) whenever a signal it read during its last run changes.

### `Memo`

`pub struct Memo<T>`: Derived state: recomputed when its inputs change; readers are notified only when the value actually changes. A `Copy` handle, owned like a `Signal`.

- `pub fn new(f: impl Fn() -> T + 'static) -> Self`: A value computed by `f` from other signals.
- `pub fn get(&self) -> T`: The current value, subscribing the running effect.
- `pub fn with<R>(&self, f: impl FnOnce(&T) -> R) -> R`: Reads the value through `f`, subscribing the running effect.
- `pub fn get_untracked(&self) -> T`: The current value, without subscribing.
- `pub fn with_untracked<R>(&self, f: impl FnOnce(&T) -> R) -> R`: Reads the value through `f` without subscribing.

### `Signal`

`pub struct Signal<T>`: Mutable state: a `Copy` handle (closures capture it as is). It belongs to the owner current when it was made (see the module docs) and is freed with it; afterwards reading it panics and setting it does nothing.

- `pub fn new(value: T) -> Self`: A signal holding `value`, owned by the current owner (if any).
- `pub fn is_alive(&self) -> bool`: Whether the signal still exists (its owner hasn't been dropped).
- `pub fn try_get(&self) -> Option<T> where T: Clone`: A copy of the value, subscribing the running effect; `None` once the signal was freed.
- `pub fn with<R>(&self, f: impl FnOnce(&T) -> R) -> R`: Reads the value through `f`, subscribing the running effect.
- `pub fn get(&self) -> T where T: Clone`: A copy of the value, subscribing the running effect.
- `pub fn get_untracked(&self) -> T where T: Clone`: A copy of the value, without subscribing.
- `pub fn with_untracked<R>(&self, f: impl FnOnce(&T) -> R) -> R`: Reads the value through `f` without subscribing: like `with`, for a large value (a `Vec`, a tree) that an effect reads but shouldn't re-run for.
- `pub fn set(&self, value: T)`: Replaces the value and notifies readers (nothing, once freed).
- `pub fn set_if_changed(&self, value: T) where T: PartialEq`: Replaces the value and notifies readers only if it changed.
- `pub fn update(&self, f: impl FnOnce(&mut T))`: Changes the value in place and notifies readers (nothing, once freed).

## view

- `pub fn dynamic<V: View>(f: impl Fn() -> V + 'static) -> Dynamic`: A region rebuilt when the signals `f` reads change (see `Dynamic`).
- `pub fn for_each<T, V>(items: impl Fn() -> Vec<T> + 'static, row: impl Fn(T) -> V + 'static) -> ForEach where T: Identifiable + 'static, V: View`: One view per item from `items` (re-run when the signals it reads change).
- `pub fn grid(rows: impl IntoIterator<Item = impl Views>) -> Grid`: A grid from rows of views (rows may be shorter than others).
- `pub fn hstack(children: impl Views) -> Stack`: Children left to right.
- `pub fn zstack(children: impl Views) -> Layers`: Children on top of one another, the first at the back: text or a glass panel over a picture, a badge over an icon. The stack is as large as its largest child. Children that fill (a picture with `.fill_width()` and `.fill_height()`) take its whole size; the others keep their own and are centred, or placed by `alignment`.
- `pub fn live_nodes() -> usize`: Number of live nodes (diagnostic, for teardown checks).
- `pub fn spacer() -> Spacer`: Flexible empty space along its stack's axis.
- `pub fn vstack(children: impl Views) -> Stack`: Children top to bottom.
- `pub fn watch(f: impl FnMut() + 'static) -> Watch`: A side effect owned by the view tree (see `Watch`).

### `Align`

`pub enum Align`: Alignment across a stack's axis.

- `Start`: Leading (vertical stacks) or top (horizontal stacks).
- `Center`: Centred.
- `End`: Trailing or bottom.

### `AnyView`

`pub struct AnyView`: A type-erased view (any `View` converts into one).

- `pub fn new(view: impl View) -> Self`: Erases `view`.

### `Axis`

`pub enum Axis`: Stack direction.

- `Horizontal`: Children left to right.
- `Vertical`: Children top to bottom.

### `Cx`

`pub struct Cx`: Where a view is being built: the native view its leaves are added to.

### `Dynamic`

`pub struct Dynamic(Box<dyn Fn() -> AnyView>)`: A region whose content is rebuilt when the signals `f` reads change. If the new view has the same `.id(..)` as the current one, the current node (and its native views) is kept.

### `ForEach`

`pub struct ForEach(Box<dyn FnOnce(&mut Cx) -> Node>)`: One view per item. When the items change, items whose id is still present keep their node (and native views); new ones are built; removed ones are torn down. Order follows the items.

### `Grid`

`pub struct Grid`: Rows of cells in aligned columns: each column is as wide as its widest cell, each row as tall as its tallest. Columns (rows) with a flexible cell share the extra space.

- `pub fn align_column(mut self, column: usize, align: Align) -> Self`: Horizontal alignment of the cells in `column` (default leading). Mac forms right-align their label column: `.align_column(0, Align::End)`.
- `pub fn spacing(mut self, columns: f64, rows: f64) -> Self`: Space between columns and between rows (default 8, 8).

### `Identifiable` (trait)

`pub trait Identifiable`: Items with a stable identity, for `for_each`.

- `type Id: Hash + Eq + Clone + 'static`: The identity type.
- `fn id(&self) -> Self::Id`: This item's identity.

### `Modified`

`pub struct Modified<V>`: A view with modifiers applied (see `ViewExt`). Layout and look modifiers apply in the order written, as SwiftUI's do: `.frame(18.0, 18.0).padding(7.0)` is an 18-point view with 7 points around it, and `.padding(16.0).background(..)` puts the background under the padding too, while `.background(..).padding(16.0)` doesn't.

- `pub fn popover<P: View>(self, shown: &Signal<bool>, content: impl Fn() -> P + 'static) -> Self`: Shows `content` in a popover pointing at this view while `shown` is true; closing it (Escape, a click outside) sets `shown` to false. The content is built each time it opens and freed when it closes.
- `pub fn popover_on<P: View>(mut self, edge: crate::Edge, shown: &Signal<bool>, content: impl Fn() -> P + 'static) -> Self`: `popover` on a given side of the view.
- `pub fn on_command(mut self, command: crate::Command, action: impl Fn() + 'static) -> Self`: Handles `command` while the focus is in this view (or nothing nearer the focus handles it). See `Command`.
- `pub fn on_command_when(mut self, command: crate::Command, enabled: impl Fn() -> bool + 'static, action: impl Fn() + 'static) -> Self`: Handles `command` like `on_command`, enabled only while `enabled` returns true (a disabled handler still answers: the menu item is greyed out, and handlers further out aren't asked).
- `pub fn focused_value<T: Clone + 'static>(mut self, name: &'static str, value: T) -> Self`: Publishes `value` under `name` while the focus is in this view, for `focused_value` (a signal, typically: the list's selection, the editor's document).
- `pub fn accessibility_label(mut self, label: &str) -> Self`: The name VoiceOver reads for this view's native views.
- `pub fn context_menu(mut self, items: Vec<crate::chrome::MenuItem>) -> Self`: A right-click menu on this view's native views.
- `pub fn fill_width(mut self) -> Self`: Takes all the width its container offers.
- `pub fn fill_height(mut self) -> Self`: Takes all the height its container offers.
- `pub fn padding(mut self, points: f64) -> Self`: Inset on all sides, in points.
- `pub fn padding_xy(mut self, horizontal: f64, vertical: f64) -> Self`: Inset left and right, and above and below (see `ViewExt::padding_xy`).
- `pub fn width(mut self, points: f64) -> Self`: A fixed width.
- `pub fn min_width(mut self, points: f64) -> Self`: A minimum width (see `ViewExt::min_width`).
- `pub fn min_height(mut self, points: f64) -> Self`: A minimum height (see `ViewExt::min_height`).
- `pub fn height(mut self, points: f64) -> Self`: A fixed height.
- `pub fn background(mut self, color: impl crate::IntoValue<crate::Color>) -> Self`: A background behind the view (see `ViewExt::background`).
- `pub fn corner_radius(mut self, points: f64) -> Self`: Rounded corners for the background and border.
- `pub fn border(mut self, color: crate::Color, width: f64) -> Self`: A border around the view.
- `pub fn shadow(mut self, shadow: crate::Shadow) -> Self`: A drop shadow under the view's background.
- `pub fn opacity(mut self, opacity: impl crate::IntoValue<f64>) -> Self`: The view at `opacity` (see `ViewExt::opacity`).
- `pub fn font(mut self, font: crate::Font) -> Self`: The font of the text inside (see `ViewExt::font`).
- `pub fn color(mut self, color: impl crate::IntoValue<crate::Color>) -> Self`: The colour of the text and symbols inside (see `ViewExt::color`).
- `pub fn accessibility_value(mut self, value: impl crate::IntoValue<String>) -> Self`: What VoiceOver reads as the value (see `ViewExt::accessibility_value`).
- `pub fn material(mut self, material: crate::Material) -> Self`: A system material behind the view (see `ViewExt::material`).
- `pub fn glass(mut self, glass: crate::Glass) -> Self`: Liquid Glass behind the view (see `ViewExt::glass`).
- `pub fn background_when(self, color: impl Fn() -> crate::Color + 'static) -> Self`: A background following signals (now `background` takes a closure).
- `pub fn opacity_when(self, opacity: impl Fn() -> f64 + 'static) -> Self`: Opacity following signals (now `opacity` takes a closure).
- `pub fn matched_geometry(mut self, id: &str) -> Self`: Matched geometry (see `ViewExt::matched_geometry`).
- `pub fn transition(mut self, transition: crate::Transition) -> Self`: How the view comes and goes (see `ViewExt::transition`).

### `View` (trait)

`pub trait View: 'static`: Something that can be shown. Build-once: `View::build` creates native views and effects; it is never called again for the same place.

- `fn build(self, cx: &mut Cx) -> Node`: Creates the node (native views are added to `cx`'s container).
- `fn id(self, id: impl Hash) -> AnyView where Self: Sized`: Gives the view an identity: a `dynamic` region keeps the existing node instead of rebuilding when the new view has the same id.

### `ViewExt` (trait)

`pub trait ViewExt: View + Sized`: Modifiers every view has.

- `fn on_command(self, command: crate::Command, action: impl Fn() + 'static) -> Modified<Self>`: Handles `command` while the focus is in this view (see `Command`).
- `fn on_command_when(self, command: crate::Command, enabled: impl Fn() -> bool + 'static, action: impl Fn() + 'static) -> Modified<Self>`: Handles `command`, enabled only while `enabled` returns true.
- `fn focused_value<T: Clone + 'static>(self, name: &'static str, value: T) -> Modified<Self>`: Publishes `value` under `name` to the focus (see `focused_value`).
- `fn padding(self, points: f64) -> Modified<Self>`: Inset on all sides, in points.
- `fn padding_xy(self, horizontal: f64, vertical: f64) -> Modified<Self>`: Inset `horizontal` points left and right and `vertical` above and below: a row's `.padding_xy(10.0, 7.0)`, as SwiftUI's `.padding(.horizontal, 10)` and `.padding(.vertical, 7)`.
- `fn width(self, points: f64) -> Modified<Self>`: A fixed width.
- `fn min_width(self, points: f64) -> Modified<Self>`: At least `points` wide (SwiftUI's `frame(minWidth:)`).
- `fn min_height(self, points: f64) -> Modified<Self>`: At least `points` tall (SwiftUI's `frame(minHeight:)`).
- `fn height(self, points: f64) -> Modified<Self>`: A fixed height.
- `fn frame(self, width: f64, height: f64) -> Modified<Self>`: A fixed size.
- `fn fill_width(self) -> Modified<Self>`: Takes all the width its container offers.
- `fn fill_height(self) -> Modified<Self>`: Takes all the height its container offers.
- `fn popover<P: View>(self, shown: &Signal<bool>, content: impl Fn() -> P + 'static) -> Modified<Self>`: Shows `content` in a popover pointing at this view while `shown` is true (see `Modified::popover`).
- `fn context_menu(self, items: Vec<crate::chrome::MenuItem>) -> Modified<Self>`: A right-click menu on this view's native views.
- `fn accessibility_label(self, label: &str) -> Modified<Self>`: The name VoiceOver reads for this view's native views ("Name", "Volume"), for controls whose visible label is a separate view or that have none (a field after a `text("Name:")`, an icon button).
- `fn background(self, color: impl crate::IntoValue<crate::Color>) -> Modified<Self>`: A background behind the view, its padding included: with `corner_radius` and `shadow`, a card. `Color::QuaternaryFill` is the system's grouped-card colour. A closure computes it from signals (a selected row, a status); it changes smoothly inside `animated`.
- `fn corner_radius(self, points: f64) -> Modified<Self>`: Rounds the corners of the view's background and border, in points.
- `fn border(self, color: crate::Color, width: f64) -> Modified<Self>`: A border `width` points wide around the view (inside its padding).
- `fn shadow(self, shadow: crate::Shadow) -> Modified<Self>`: A drop shadow under the view's background (give it a background).
- `fn opacity(self, opacity: impl crate::IntoValue<f64>) -> Modified<Self>`: The view at `opacity` (0 transparent, 1 opaque), all of it, or a closure computing it from signals; it fades inside `animated`.
- `fn font(self, font: crate::Font) -> Modified<Self>`: The font of the text inside the view (all of it, when it's a row or a card): a text style or a custom font. Works after any modifier.
- `fn color(self, color: impl crate::IntoValue<crate::Color>) -> Modified<Self>`: The colour of the text and symbols inside the view, or a closure computing it from signals. Works after any modifier.
- `fn accessibility_value(self, value: impl crate::IntoValue<String>) -> Modified<Self>`: What VoiceOver reads as the view's value, after its name: a card's state ("done"), a gauge's level. A closure keeps it current.
- `fn material(self, material: crate::Material) -> Modified<Self>`: A system material behind the view, its padding included: a translucent sidebar, header or panel that blurs what's behind it. `corner_radius` rounds it.
- `fn glass(self, glass: crate::Glass) -> Modified<Self>`: Liquid Glass behind the view, its padding included (macOS 26; a translucent material on macOS 15). `corner_radius` rounds it.
- `fn background_when(self, color: impl Fn() -> crate::Color + 'static) -> Modified<Self>`: A background following signals (now `background` takes a closure).
- `fn opacity_when(self, opacity: impl Fn() -> f64 + 'static) -> Modified<Self>`: Opacity following signals (now `opacity` takes a closure).
- `fn transition(self, transition: crate::Transition) -> Modified<Self>`: How the view comes and goes when it's added or removed (by `dynamic` or `for_each`) inside `animated`.
- `fn matched_geometry(self, id: &str) -> Modified<Self>`: Matched geometry (SwiftUI's `matchedGeometryEffect`): when, in one `animated` change, a view with this `id` goes and another with it comes (a thumbnail replaced by its detail, a selection marker moving), the new one starts where and as large as the old one was, and moves to its place.
- `fn on_hover(self, action: impl Fn(bool) + 'static) -> Modified<Self>`: Calls `action` with `true` when the pointer moves over the view and `false` when it leaves (while the app is active).
- `fn hover_highlight(self, color: crate::Color) -> Modified<Self>`: A background of `color` while the pointer is over the view, fading in and out: for rows and cards that can be clicked.
- `fn tooltip(self, text: &str) -> Modified<Self>`: A tooltip: `text` appears in a small box when the pointer rests on the view (SwiftUI's `help`). VoiceOver reads it as the view's help.
- `fn hidden(self, when: impl crate::IntoValue<bool>) -> Modified<Self>`: Hides the view while `when()` is true, following the signals it reads: its native views stay built (no rebuild, the state inside kept) but aren't shown, and it takes no room in its stack, as if it weren't there. For a panel shown in one mode only, rather than a `dynamic` that rebuilds it each time. VoiceOver and Tab skip it.
- `fn disabled(self, when: impl crate::IntoValue<bool>) -> Modified<Self>`: Disables the view's controls while `when()` is true (a picker that only matters once a checkbox is on, a form while it's saving), following the signals it reads. SwiftUI's `disabled`.
- `fn on_click(self, action: impl Fn() + 'static) -> Modified<Self>`: Makes the whole view a button: a click on it calls `action`, it dims while pressed, and VoiceOver reads it as a button named by its text. For rows, cards and tiles; controls inside it don't get clicks.

- `pub fn on_sort(mut self, f: impl Fn(Sort) + 'static) -> Self`: The user sorted by a column (rows are already shown in the new order).
- `pub fn on_toggle(mut self, f: impl Fn(usize, String, bool) + 'static) -> Self`: A checkbox cell was clicked: (row, column id, new value).
- `pub fn on_edit(mut self, f: impl Fn(usize, String, String) + 'static) -> Self`: An editable cell was edited: (row, column id, new text). Apply it to the row with `TableModel::update_row`.

### `TableModel`

`pub struct TableModel<T: 'static>`: A native table backed by rows of `T`. See the module docs.

- `pub fn new(id: ViewId, columns: Vec<Column<T>>) -> Self`: Creates the native table (not yet in a window: it's added the first time the host draws it, see `TableModel::ensure_mounted`).
- `pub fn id(&self) -> ViewId`: The view id the table was created with.
- `pub fn ensure_mounted(&self)`: Adds the table to the attached window if it isn't yet. Called by the host widget before placing it.
- `pub fn set_columns(&self, columns: Vec<Column<T>>)`: Replaces the columns, keeping the same native table (a query browser's results change shape with every query). The sort is cleared. Call `set_rows` after it when the rows change too: nothing is drawn in between.
- `pub fn set_rows(&self, rows: Vec<T>)`: Replaces all rows (the current sort is applied). Clears the selection.
- `pub fn rows(&self) -> Ref<'_, Vec<T>>`: The rows, in model order (unsorted).
- `pub fn len(&self) -> usize`: Number of rows.
- `pub fn is_empty(&self) -> bool`: Whether there are no rows.
- `pub fn update_row(&self, index: usize, row: T)`: Replaces one row. Redraws only that row unless the table is sorted (then the order is recomputed; the selection is kept).
- `pub fn insert(&self, index: usize, row: T)`: Inserts a row at a model index (the selection is kept).
- `pub fn append(&self, rows: Vec<T>)`: Appends rows in one step, for live data (a log tail, a feed): when unsorted, the new rows are added to the end and AppKit only learns the new count (cost independent of the rows already there; the selection is kept). When sorted, the order is recomputed.
- `pub fn scroll_to_end(&self)`: Scrolls so the last row is visible.
- `pub fn is_at_end(&self) -> bool`: Whether the table is scrolled to its last row (within one row), e.g. to keep following new rows only while the user hasn't scrolled up.
- `pub fn push(&self, row: T)`: Appends a row.
- `pub fn remove(&self, index: usize) -> Option<T>`: Removes a row (the selection is kept for the other rows).
- `pub fn move_rows(&self, rows: &[usize], before: Option<usize>) -> Vec<usize>`: Moves `rows` (model indices) to just above the row `before` (or to the end), keeping their order, as a drop reported by `TableEvent::RowsMoved` asks. Returns their new model indices; they end up selected.
- `pub fn set_row_drag(&self, on: bool)`: Lets rows be dragged out: each carries its cells as tab-separated text (for other apps), and its model index for `set_reorderable`. Off by default (a drag then extends the selection).
- `pub fn set_reorderable(&self, on: bool)`: Lets the user drag rows to a new place (also turns on `set_row_drag`); each drop is reported as `TableEvent::RowsMoved`. Refused while the table is sorted.
- `pub fn set_file_drop(&self, extensions: Option<&[&str]>)`: Accepts files dropped from the Finder: `Some(&["csv", "txt"])` for those extensions, `Some(&[])` for any file, `None` to stop. Each drop is reported as `TableEvent::FilesDropped`.
- `pub fn set_animates(&self, on: bool)`: Rows added by `insert` and `push`, and removed by `remove`, fade and slide in and out instead of appearing at once; the other rows keep their cells. Not in a grouped table, and not for `set_rows` or `append` (whole lists and live feeds). Off by default.
- `pub fn set_url_drop(&self, on: bool)`: Accepts web addresses dragged from a browser (a link, or the address bar's icon). Each drop is reported as `TableEvent::UrlsDropped`. Off by default.
- `pub fn set_pastes(&self, on: bool)`: Reports ⌘V on the table as `TableEvent::Paste` (and enables Paste in the Edit menu while there is text to paste). Off by default.
- `pub fn set_keys(&self, keys: &[TableKey])`: Reports these keys, pressed without ⌘, ⌥ or ⌃ while rows are selected, as `TableEvent::Key` instead of AppKit's handling (Space would type-select, Delete beep). None by default.
- `pub fn set_cell_focus(&self, on: bool)`: Cell focus, as in a spreadsheet: the table keeps a focused column, which a click on a cell moves to its column and ← and → move one column at a time (`TableEvent::FocusedColumn`). The focused cell of each selected row is outlined. With the selection it names the cells an action applies to (Set to NULL, Copy Cell). Off by default.
- `pub fn focused_column(&self) -> Option<String>`: The focused column's id (see `set_cell_focus`).
- `pub fn set_focused_column(&self, column: Option<&str>)`: Focuses a column by id (`None`: no column), scrolling it into view. Doesn't report an event.
- `pub fn focus_ring(&self, view_row: usize) -> Option<(f64, f64, f64, f64)>`: The focused cell's outline in row `view_row` (a view position), in the row's coordinates, if the row is shown, selected and a column is focused. For checks.
- `pub fn selected_text(&self) -> String`: The selected rows as tab-separated text (columns in their current order, one line per row, as ⌘C copies them).
- `pub fn copy_to(&self, pasteboard: &NSPasteboard) -> bool`: Copies the selected rows to `pasteboard` (what ⌘C does with the general pasteboard). False if nothing is selected.
- `pub fn paste_from(&self, pasteboard: &NSPasteboard) -> bool`: Pastes `pasteboard`'s text (what ⌘V does with the general pasteboard): queues `TableEvent::Paste` if the table takes pastes.
- `pub fn row_at(&self, position: usize) -> Option<usize>`: The model index of the row shown at `position` (0 = top row as currently sorted); `None` past the end or for a group header.
- `pub fn set_group_by(&self, key: Option<GroupKey<T>>)`: Groups the rows under headers by `key` (e.g. a date or a category): groups appear in the order their first row has in the model, rows keep the sort's order within each group, and each group starts with a header row showing the key (full width, not selectable, floating while its rows scroll). `None` ungroups. Row indices in events stay model indices.
- `pub fn groups(&self) -> Vec<String>`: The groups' titles, in the order shown (empty when not grouped).
- `pub fn shown_rows(&self) -> usize`: The number of rows shown, group headers included.
- `pub fn selection(&self) -> Vec<usize>`: Selected rows (model indices, ascending in view order).
- `pub fn select(&self, rows: &[usize])`: Selects rows by model index (emits no event).
- `pub fn sort(&self) -> Option<Sort>`: The current sort, if any.
- `pub fn set_sort(&self, sort: Option<Sort>)`: Sets the sort (shown in the header) and, with built-in sorting, applies it.
- `pub fn set_sorts_in_place(&self, on: bool)`: Built-in sorting (default on): header clicks reorder the rows here. Turn it off to sort yourself on `TableEvent::Sort` (e.g. in a database) and call `TableModel::set_rows`.
- `pub fn column_state(&self) -> Vec<ColumnState>`: Columns in their current order, with widths.
- `pub fn set_column_state(&self, state: &[ColumnState])`: Restores a saved arrangement (unknown ids are ignored).
- `pub fn drain_events(&self) -> Vec<TableEvent>`: Takes the queued user events (for the host widget).
- `pub fn cells_created(&self) -> usize`: Diagnostics: cell views created so far (reuse keeps this near the number of visible cells).
- `pub fn scroll_view(&self) -> Retained<NSScrollView>`: The `NSScrollView` holding the table, for hosts that place it themselves (no `crate::attach`ed window).
- `pub fn table_view(&self) -> Retained<NSTableView>`: The underlying `NSTableView` (escape hatch).

- `pub fn set_grammar_checking(&self, on: bool)`: Grammar checking (off by default).

### `Resource`

`pub struct Resource<T>`: A value loaded on a background thread from inputs read on the main thread. - `pub fn error(&self) -> Option<String>`: The error of the latest finished load, if it failed.
- `pub fn state(&self) -> Load<T>`: Loading, the latest value, or the latest error: whichever the most recent finished load produced (`Loading` only before the first).
- `pub fn refetch(&self)`: Loads again with the same inputs (the running load is cancelled).

## motion

- `pub fn animate(value: &Signal<f64>, to: f64, animation: Animation)`: Animates `value` from where it is to `to` with `animation`, setting it every frame (about 120 times a second): views and drawings that read it follow. A spring passes `to` and comes back; a new animation of the same signal takes over from where it is. With Reduce Motion on, it's set to `to` at once.
- `pub fn animated<R>(f: impl FnOnce() -> R) -> R`: Runs `f` (as a `batch`) and animates what it changes: views that move or resize because of it, opacity and colours set by `opacity_when` and `background_when`, and views with a `transition` that come or go. Over a quarter of a second, easing in and out.
- `pub fn animated_with<R>(animation: Animation, f: impl FnOnce() -> R) -> R`: `animated` with your own timing.
- `pub fn keyframes(value: &Signal<f64>, frames: Keyframes)`: Takes `value` through `frames` (SwiftUI's keyframe animator): a pulse, a shake, a count-up, a bounce; each step reached with its own timing. Reduce Motion skips to the last value (a repeating one stays at its start).
- `pub fn reduce_motion() -> bool`: Whether the user asked for less motion (System Settings › Accessibility › Display › Reduce motion). Animated changes respect it on their own.
- `pub fn stop_animation(value: &Signal<f64>)`: Stops animating `value` (where it is now).

### `Animation`

`pub struct Animation`: How an animated change moves (see `animated_with`).

- `pub fn ease_in_out(seconds: f64) -> Animation`: Easing in and out over `seconds`: for things that move.
- `pub fn ease_out(seconds: f64) -> Animation`: Starting fast and settling over `seconds`: for things that appear.
- `pub fn ease_in(seconds: f64) -> Animation`: Starting slowly over `seconds`: for things that leave.
- `pub fn linear(seconds: f64) -> Animation`: At a constant pace over `seconds`.
- `pub fn spring(response: f64, damping: f64) -> Animation`: A spring, as SwiftUI's: `response` is how quickly it moves (its period undamped, in seconds), `damping` how it settles: 1 without overshooting, less with a bounce (0.5 bounces a few times). It lasts until it's still. Things moved by a spring can be moved again mid-flight: they go on from where they are.
- `pub fn bouncy() -> Animation`: A spring with a visible bounce, about a tenth past the end (response 0.5, damping 0.6).
- `pub fn snappy() -> Animation`: A quick spring with a hint of bounce (response 0.3, damping 0.85).
- `pub fn smooth() -> Animation`: A spring that settles without overshooting (response 0.5, damping 1).
- `pub fn progress(&self, seconds: f64) -> f64`: How far along it is `seconds` in: 0 at the start, 1 at the end (a spring passes 1 and comes back).
- `pub fn duration(&self) -> f64`: How long it takes, in seconds.

### `Keyframes`

`pub struct Keyframes`: Values a signal goes through over time, each reached with its own animation (see `keyframes`).

- `pub fn new(value: f64) -> Keyframes`: Keyframes starting at `value` (or, with `from_current`, wherever the signal is).
- `pub fn from_current() -> Keyframes`: Keyframes starting wherever the signal is.
- `pub fn to(self, value: f64, seconds: f64) -> Keyframes`: Then to `value` over `seconds`, easing in and out.
- `pub fn linear(self, value: f64, seconds: f64) -> Keyframes`: Then to `value` at a constant pace over `seconds`.
- `pub fn with(mut self, value: f64, animation: Animation) -> Keyframes`: Then to `value` with `animation` (a spring, say).
- `pub fn repeating(mut self) -> Keyframes`: Over again from the start when it ends, until `stop_animation` (or the signal goes).
- `pub fn duration(&self) -> f64`: How long one run takes, in seconds.

### `Transition`

`pub enum Transition`: How a view comes and goes when it's added or removed inside `animated` (see `ViewExt::transition`). Outside an animation it appears and disappears at once.

- `Fade`: Fades in and out.
- `Slide(Edge)`: Fades while sliding a short way in from the edge, and back out to it. With Reduce Motion on, it only fades.

- `pub fn check_in_background()`: Checks without showing anything unless there's an update (as Sparkle's scheduled checks do). With automatic checks and downloads both on, an update is downloaded and installed when the app quits; otherwise Sparkle shows it.
- `pub fn can_check() -> bool`: Whether a check can start now (there's Sparkle and none is running).
- `pub fn automatic_checks() -> bool`: Whether Sparkle checks on its schedule (daily by default). Sparkle asks the user at the second launch; this is their answer, or what the app set.
- `pub fn set_automatic_checks(on: bool)`: Turns scheduled checks on or off (a Settings checkbox, say). Kept in the app's defaults.
- `pub fn automatic_downloads() -> bool`: Whether updates found by scheduled checks download on their own and install when the app quits (Sparkle does this only while automatic checks are on too).
- `pub fn set_automatic_downloads(on: bool)`: Turns automatic downloads on or off. Kept in the app's defaults.
- `pub fn last_check() -> Option<SystemTime>`: When Sparkle last checked, if it has.
- `pub fn on_event(f: impl Fn(&UpdateEvent) + 'static)`: Calls `f` with what the updater does: found an update, up to date, ready to install on quit, failed. Sparkle shows its own windows for checks the user starts; this is for the app's own status (a badge, a line in Settings) and for checks.

## Module `testing`

Helpers for automated checks of apps built with ferrokit: the accessibility tree as VoiceOver sees it, key equivalents through the menu, simulated edits, memory footprint and window snapshots. Used by the checklist and the example apps' self-checks.

### testing

- `pub fn check(name: &str, pass: bool, note: impl std::fmt::Display)`: Reports one self-check as `cargo ferrokit check` reads them: prints `[check] <name> PASS <note>` or `FAIL`, and counts the failures for `finish`. Put what was seen in `note`, so a failure says why.
- `pub fn skip(name: &str, why: impl std::fmt::Display)`: Reports a self-check that couldn't run here (the screen is locked, a permission isn't granted): `[check] <name> SKIP <why>`. Not a failure; `cargo ferrokit check` counts it apart.
- `pub fn finish() -> !`: Ends a self-check run: prints `[check] done, <n> failed` and exits, with a failing status if any `check` failed.
- `pub fn steps(pause_ms: u64, steps: Vec<Box<dyn FnOnce()>>)`: Runs `steps` one after another, each in a turn of its own `pause_ms` after the one before, then `finish`es. A self-check acts in one step and looks in the next: effects, table updates and sheets settle after the step that caused them returns.
- `pub fn view_labeled(window: &objc2_app_kit::NSWindow, label: &str) -> Option<Retained<objc2_app_kit::NSView>>`: The first view in `window` with the accessibility label `label` (what `.accessibility_label(..)` set), for a check to read or drive: a field, a table, an editor's text view, a web view.
- `pub fn footprint_mb() -> f64`: Physical footprint in MB (what Activity Monitor shows; RSS keeps freed heap pages and overstates growth), via vmmap.
- `pub fn peak_footprint_mb() -> f64`: The process's peak physical footprint so far, in MB (via vmmap).
- `pub fn ax_tree(window: &objc2_app_kit::NSWindow) -> Vec<(String, String, String)>`: The window's accessibility tree, flattened: (role, subrole, label/title) for every element under the content view, as VoiceOver sees it. On macOS 27, AppKit's text fields and checkboxes host SwiftUI internally, so the AX element is a child of the NSView, not the view itself.
- `pub fn has_ax(tree: &[(String, String, String)], role: &str, subrole: &str, label: &str) -> bool`: Whether the tree has an element with this role (and subrole and label, unless empty).
- `pub fn post_edit(field: &NSTextField, text: &str)`: Sets a text field's text and posts the change notification, as typing does.
- `pub fn send_action(control: &objc2_app_kit::NSControl) -> bool`: Sends a control's action to its target, as a click or Return does.
- `pub fn symbol_effects() -> (isize, usize)`: Symbol effects running (`Image::effect` while active) and one-shot effects played so far (`Image::effect_on`).
- `pub fn step_motion(seconds: f64)`: Moves the clock springs, `animate` and `keyframes` run on forward by `seconds` and runs a frame: what's animating lands where it would be that much later.
- `pub fn set_right_to_left(on: Option<bool>)`: Lays out right to left (`Some(true)`), left to right, or as the app's language says (`None`): for checking a layout mirrors. Windows lay out again as they change; call it before opening the window to check.
- `pub fn remember_open_documents()`: Remembers the documents open now, as quitting does (they reopen at the next launch when the user keeps windows: `NSQuitAlwaysKeepsWindows`, which a launch argument can set for one run).
- `pub fn motion_running() -> usize`: Value and spring animations running now.
- `pub fn failures() -> Vec<crate::Failure>`: The failures caught where AppKit called in (exceptions and panics; the last 100): see `App::on_error`.
- `pub fn thumbnails_made() -> usize`: Quick Look thumbnails made so far (`thumbnail`).
- `pub fn quick_look_state() -> (Vec<std::path::PathBuf>, Option<usize>)`: The files the Quick Look panel was given, and the one it shows (`None` while it's closed).
- `pub fn snapshot_windows(dir: &str)`: Renders every window to `<dir>/<title>.png` (AppKit's own drawing, no screen-recording permission needed). The window's frame view is drawn, so the image includes the title bar and the window background (which the content view alone doesn't draw).
- `pub fn key_equiv(w: &objc2_app_kit::NSWindow, chars: &str, shift: bool) -> bool`: Sends a ⌘-key equivalent through the main menu, as a key press would.
- `pub fn about_shown() -> u32`: How many times About {app} was shown with `App::about`'s credits.
- `pub fn app_menu_titles() -> Vec<String>`: The titles of the app menu's items (the first menu: About, Check for Updates…, Settings…, Hide, Quit), separators as `"-"`.
- `pub fn menu_key(chars: &str, modifiers: objc2_app_kit::NSEventModifierFlags) -> bool`: Sends a key-down with `chars` and `modifiers` to the main menu's key equivalents (no window needed); true if an enabled item took it.
- `pub fn shortcut(window: &objc2_app_kit::NSWindow, chars: &str, shift: bool) -> bool`: Performs a keyboard shortcut the way the menu bar does, without needing the app to be active: finds the main-menu item for ⌘`chars` (⇧⌘ when `shift`; AppKit's rule: an uppercase key equivalent implies Shift). An item of the app's own (`menu_item`, `menu_command`) runs if it's enabled; a standard item (Undo, Select All) sends its action along `window`'s responder chain, starting at its first responder. Returns whether an item matched and something handled it.
- `pub fn set_preview_mode(on: bool)`: Turns preview mode on or off for windows opened from now on, as `cargo ferrokit preview` does with `FERROKIT_PREVIEW=1`: a window without `remember_frame` keeps its frame under its title.
- `pub fn capture_reveals(on: bool)`: From now on, `reveal_in_finder` records what it's asked to show instead of opening Finder windows (`false` stops).
- `pub fn revealed() -> Vec<Vec<std::path::PathBuf>>`: What `reveal_in_finder` was asked to show since the last call, while `capture_reveals` is on: one list of paths per call.
- `pub fn set_last_opened(path: &std::path::Path, secs: Option<i64>) -> std::io::Result<()>`: Sets `path`'s last-opened date (seconds since 1970, `None` for never), for checks of lists that use `file_dates`.
- `pub fn catching(f: impl FnOnce())`: Runs `f` the way Ferrokit runs code AppKit calls in (an action, a timer): a panic in it is caught and reported (see `failures`), not a crash.
- `pub fn pending_crash_reports(dir: &std::path::Path) -> Vec<crate::CrashReport>`: The crash reports in `dir` not yet marked sent, oldest first (what `App::crash_reports` hands the app at launch). Checks point `FERROKIT_CRASH_DIR` at a folder of their own.
- `pub fn is_misspelled(word: &str) -> bool`: Whether the system spell checker flags `word` in English. (With automatic language detection one isolated word can be guessed as another language and pass, so the language is given.)
- `pub fn context_menu_for_word(view: &objc2_app_kit::NSTextView, word: &str) -> Vec<String>`: The titles of a text view's context menu for a right-click on `word`.
- `pub fn capture_window(window: &objc2_app_kit::NSWindow) -> Option<Retained<objc2_app_kit::NSBitmapImageRep>>`: Captures `window` as the window server shows it (lossless, no shadow, via `screencapture -l`): what's on screen, which in-process snapshots can miss (Core Animation layers, animations, vibrancy). Needs the screen-recording permission; `None` without it.
- `pub fn captured_pixels(rep: &objc2_app_kit::NSBitmapImageRep, view: &objc2_app_kit::NSView, step: usize) -> Vec<Vec<(f64, f64, f64)>>`: The sRGB colours (r, g, b in 0…1) of a capture from `capture_window` inside `view`'s bounds: rows from the top, every `step` pixels.
- `pub fn ax_elements(window: &objc2_app_kit::NSWindow) -> Vec<AxElement>`: Every accessibility element under `window`'s content view, depth first.
- `pub fn ax_audit(window: &objc2_app_kit::NSWindow) -> Vec<String>`: What VoiceOver users would miss in `window`: controls with no name to read (fields, editors, sliders, pop-ups, checkboxes, switches, buttons, steppers), and images and controls read as a symbol name ("speaker.wave.2"). Empty when every control can be told apart by ear.
- `pub fn heap_in_use_mb() -> f64`: Memory the process has allocated and not freed, in MB (all malloc zones). Unlike `footprint_mb`, it drops as soon as something is freed: the allocator returns freed pages to the system in batches, at times of its own (seconds later when the machine is busy), so footprint can't tell a leak from memory not yet handed back. Use this for leak checks.
- `pub fn virtual_machine() -> bool`: Whether this Mac is a virtual machine (GitHub's macOS runners are). There the window server has no GPU, so materials don't blur, drawing is slower and window-server input doesn't arrive: checks of those say SKIP rather than fail.
- `pub fn canvas_drawing(view: &objc2_app_kit::NSView) -> Option<Vec<String>>`: What a `canvas` (or chart) drew last, one line per operation (`fill rect 10,20 30x40 Blue`, `text "Jan" 11pt`); `None` if `view` isn't one.
- `pub fn canvas_png(view: &objc2_app_kit::NSView) -> Option<Vec<u8>>`: A canvas as a PNG, on the content background: what its Copy Image puts on the clipboard. `None` if `view` isn't a canvas.
- `pub fn canvas_click(view: &objc2_app_kit::NSView, x: f64, y: f64) -> bool`: Clicks a `canvas` at `x, y` (points from its top left), running its `on_click` handler; false if it has none.
- `pub fn canvas_scroll(view: &objc2_app_kit::NSView, dx: f64, dy: f64, x: f64, y: f64) -> bool`: Scrolls a `canvas` (or chart) by `dx, dy` points with the pointer at `x, y`, as a trackpad would; false if it didn't use it.
- `pub fn canvas_magnify(view: &objc2_app_kit::NSView, amount: f64, x: f64, y: f64) -> bool`: Pinches a `canvas` (or chart) by `amount` (0.5 is 50% larger) at `x, y`; false if it didn't use it.
- `pub fn canvas_drag(view: &objc2_app_kit::NSView) -> Option<crate::DragItem>`: What dragging a canvas would carry now (its `draggable`, or the image of an `exportable` one), without a drag session.
- `pub fn canvas_move(view: &objc2_app_kit::NSView, from: (f64, f64), to: (f64, f64)) -> bool`: Drags inside a canvas from `from` to `to` (its coordinates), as a user's drag reaches its `on_drag`; false without one.
- `pub fn fulfil(item: &crate::DragItem, dir: &std::path::Path) -> std::io::Result<std::path::PathBuf>`: Writes a promised file into `dir` as a drop there would; the path.
- `pub fn drop_on_view(view: &objc2_app_kit::NSView, pasteboard: &objc2_app_kit::NSPasteboard) -> bool`: Drops whatever is on `pasteboard` onto `view` as AppKit does at the end of a drag (entered, then perform). Whether it was taken.
- `pub fn set_reduce_motion(on: Option<bool>)`: Overrides the Reduce Motion setting animated changes follow (`None`: the system's), so checks can run both paths without changing it.
- `pub fn leaving_views() -> usize`: How many native views are still animating out after a transition.
- `pub fn hover(view: &objc2_app_kit::NSView, inside: bool) -> bool`: Sends a view made with `on_hover` or `hover_highlight` (its interaction view, a `FerrokitInteraction`) the pointer entering or leaving. False if `view` isn't one.
- `pub fn press(view: &objc2_app_kit::NSView, down: bool) -> bool`: Presses (`down`) or releases a view made with `on_click` (its `FerrokitInteraction`), as the mouse does: the press dims it, the release clicks. False if `view` isn't one.
- `pub fn is_pressed(view: &objc2_app_kit::NSView) -> Option<bool>`: Whether a clickable view's interaction is pressed (`None` if `view` isn't one).
- `pub fn hold_notifications()`: Makes `notify` record notifications instead of posting them (no permission prompt, no banners); read them with `sent_notifications`.
- `pub fn sent_notifications() -> Vec<crate::SentNotification>`: The notifications recorded since `hold_notifications`, oldest first (one posted again with the same id replaces it; cancelled ones go).
- `pub fn click_notification(id: &str) -> bool`: Runs the click action of the notification `id`, as clicking it in Notification Center would; false if it has none.
- `pub fn shared_items(button: &objc2_app_kit::NSButton) -> Option<Vec<crate::ShareItem>>`: What a `share_button` would share if clicked now.
- `pub fn menu_bar_extras() -> Vec<(Retained<objc2_app_kit::NSStatusItem>, Option<Retained<objc2_app_kit::NSPopover>>)>`: The app's menu-bar extras, oldest first, each with its panel's popover (for extras with a panel).

### `AxElement`

`pub struct AxElement`: One accessibility element as VoiceOver gets it.

- `pub depth: usize`: Nesting depth under the window's content view.
- `pub role: String`: `AXButton`, `AXTextField`…
- `pub subrole: String`: `AXSwitch`, `AXSearchField`…
- `pub name: String`: What VoiceOver reads as the name: the label, else the title, else a linked title element's value, else the placeholder; for static text (labels, table and sidebar rows) and a list's items, its text.
- `pub label: String`: The element's own label (set with `accessibility_label`).

## Module `input`

Real input for checks: clicks and keystrokes that take the path a user's do, not AppKit's entry points (`performClick`, `selectRowIndexes`).

### input

- `pub fn ready(window: &NSWindow) -> bool`: Brings the app to the front and makes `window` key, so input reaches it. True once both hold (it can take a run-loop turn: call it, wait a moment, and call it again before sending input).
- `pub fn click_at_with(view: &NSView, x: f64, y: f64, mods: &[Mod]) -> bool`: Clicks `view` at `x, y` points from its top-left corner, holding `mods`.
- `pub fn click_at(view: &NSView, x: f64, y: f64) -> bool`: Clicks `view` at `x, y` points from its top-left corner.
- `pub fn click(view: &NSView) -> bool`: Clicks the middle of `view`, as the user would: the window hit-tests the point, so whatever is on top there gets the click.
- `pub fn double_click(view: &NSView) -> bool`: Double-clicks the middle of `view`.
- `pub fn key(window: &NSWindow, key: Key, mods: &[Mod])`: Presses `key` with `mods` in `window` (to its first responder, or the menus' key equivalents when ⌘ is held).
- `pub fn type_text(window: &NSWindow, text: &str)`: Types `text` into `window`'s first responder, a key at a time (capitals with ⇧, line breaks as Return).
- `pub fn server_available() -> bool`: Whether window-server input can be posted: this process is trusted for Accessibility. (Asking for it is the user's to do, in System Settings.)
- `pub fn server_click(view: &NSView) -> bool`: Clicks the middle of `view` through the window server (see the module docs); false if that isn't available.
- `pub fn server_type(text: &str) -> bool`: Types `text` through the window server (see the module docs); false if that isn't available.

## Module `soak`

Soak tests: random user actions for a long time, watching for crashes, hangs and growth.

### soak

- `pub fn action(name: &'static str, weight: u32, run: impl Fn(&mut Rng) + 'static) -> Action`: An action called `name`, picked `weight` times as often as one of weight 1.
- `pub fn run(settings: Settings, actions: Vec<Action>)`: Runs the soak, then exits the process: 0 if no hang was seen, 1 if one was. Call it from `on_launch`, once the windows are up.

### `Rng`

`pub struct Rng(u64)`: A small, seeded random generator (xorshift), for repeatable runs.

- `pub fn new(seed: u64) -> Rng`: A generator from `seed` (not 0).
- `pub fn below(&mut self, n: usize) -> usize`: A number in `0..n` (0 when `n` is 0).
- `pub fn chance(&mut self, p: f64) -> bool`: True with probability `p`.
- `pub fn pick<'a, T>(&mut self, items: &'a [T]) -> &'a T`: One of `items`.

### `Action`

`pub struct Action`: One kind of action: a name for the log, a weight, and what it does.

### `Settings`

`pub struct Settings`: How long and how fast.

- `pub duration: Duration`: How long to run.
- `pub interval: Duration`: Time between actions.
- `pub seed: u64`: The random seed.
- `pub fn from_env() -> Settings`: From the environment: `SOAK` minutes (default 10), `SOAK_SEED` (default the time), `SOAK_MS` between actions (default 120); `SOAK_ONLY=<action>` runs just that one (see `run`).
